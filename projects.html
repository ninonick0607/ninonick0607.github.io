01 Runtime UI

Runtime vehicle control and system inspection

The in-sim ImGui workspace is more than a HUD. It exposes the controls needed to operate, inspect, and tune a vehicle without leaving the running experiment.

  • Switch among position, velocity, angle, rate, and direct control modes.
  • Select and possess any registered drone, spawn new vehicles, and reset pose or rotation.
  • Watch live motor thrust, IMU, GPS, magnetometer, barometer, and controller targets.
  • Tune every stage of the cascade and save or reload PID histories during a session.
  • Move between follow, orbit, FPV, and free-camera views with adjustable distance and FOV.

02 Simulation control

Deterministic simulation timing and experiment control

QuadSim’s clock and physics stepping are explicit. That makes the same scene useful for a visual demo, a carefully inspected controller tick, or an accelerated headless experiment.

  • Pause, resume, single-step, step many ticks, and change free-running time scale.
  • Quantize requested control rates to real physics steps and expose the realized rate and timestep.
  • Use exception-safe lockstep loops that restore pause state and neutralize the vehicle on exit.
  • Reset pose, physics, controller state, simulation time, or a complete seeded episode.

03 External controller

External geometric control and adaptive disturbance compensation

The ResNet/Geometric Controller project demonstrates the deepest API boundary: Unity supplies the vehicle and sensors, while a Lee-style geometric controller owns the trajectory tracking law and returns torque plus collective thrust.

  • Runs in deterministic lockstep using the simulator’s realized timestep.
  • Tracks figure-eight, acrobatic oval, and takeoff–flip–land trajectories.
  • An adaptive JAX ResNet estimates disturbance force and adjusts desired acceleration online.
  • Supports baseline-versus-adaptive logging, path visualization, safety limits, and weight checkpoints.
  • The controller core also exposes a PX4 body-rate/thrust path for simulator-to-autopilot studies.

04 PX4 integration

PX4 integration with QuadSim as the simulated plant

In PX4 mode, the bridge streams simulated inertial, GPS, barometric, and magnetic data into PX4, waits for actuator output, applies the four returned motor commands, and advances the next physics tick.

  • MAVLink HIL sensor and actuator loop with explicit motor-order mapping.
  • One frame boundary for ENU/FLU and PX4’s NED/FRD conventions.
  • Realtime offboard control for interactive sessions and a dedicated simulation-time lockstep runner.
  • PX4-native position, acceleration, attitude, and rate/thrust setpoints.
  • Thrust calibration, motor sweeps, health checks, and frame verification tools.

05 Reinforcement learning

Deterministic reinforcement-learning environment interface

QuadSim provides the physical facts and a clean episode boundary. Python remains free to define observations, rewards, termination, policies, replay, and the training framework.

  • Atomic seeded reset and step calls prevent free-running frames between action and observation.
  • Per-drone RGB, grayscale, and metric-depth capture from a dedicated training camera.
  • Runtime box, sphere, cylinder, and goal primitives are pooled and replaced with each scenario.
  • Stable object IDs and collision events make rewards and termination unambiguous.
  • A runnable Gymnasium / Stable-Baselines3 PPO RGB-D goal-hover task covers training and evaluation.

06 Multi-agent simulation

Atomic multi-agent episode reset and simulation stepping

Multi-agent steps apply every action before physics advances, then capture all vehicle states and events at the same simulation timestamp. Stable identities survive across the complete experiment boundary.

  • Discover registered vehicles by persistent index, agent ID, and team ID.
  • Reset all poses, identities, seeded sensors, goals, and obstacles as one atomic operation.
  • Issue position, velocity, acceleration, attitude, rate, motor, or wrench actions to every agent together.
  • Receive synchronized privileged state plus agent, object, ground-contact, and invalid-state events.
  • Task-side duel helpers provide capture cones, relative geometry, rewards, and ego-centric observations.

07 Sensor suite

Multi-rate sensor simulation with explicit coordinate conventions

The vehicle publishes IMU, GPS, barometer, and magnetometer data at independent simulation-time rates, with deterministic noise and georeferenced outputs for controller, PX4, and sim-to-real workflows.

  • Body velocity, angular rate, specific force, attitude, WGS84 position, NED GPS velocity, pressure, and magnetic field.
  • Seed-derived noise streams can be replayed exactly across matching episode resets.
  • Every body-frame payload self-identifies as FLU or FRD; world fields stay canonical ENU.
  • Live UI readouts and SDK accessors make frame and magnitude sanity checks visible.
